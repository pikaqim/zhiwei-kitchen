## 第一部分：需求分析工作计划

### 1. 项目概述

#### 1.1 项目背景
移动时代下厨房场景数字化需求旺盛。现有菜谱产品（下厨房、豆果美食等）以图文为主，内容生产依赖作者实拍，门槛高、周期长。与此同时，AIGC（文生图、文生视频）技术已趋于可用，使得"输入菜谱文字 → 自动生成菜品图/步骤图/烹饪演示视频"成为可能，可大幅降低菜谱内容的生产门槛。

#### 1.2 产品定位
一个"结构化电子菜谱管理 + AIGC 内容生成 + UGC 上传"三位一体的智能菜谱平台：

1. **电子菜谱**：结构化管理菜谱（食材、用量、步骤、火候、时长），支持浏览、搜索、分类。
2. **AI 生成菜谱图**：根据菜谱文字（菜名、步骤描述）自动生成菜品封面图与步骤配图。
3. **AI 生成烹饪视频**：根据菜谱文字生成短视频形态的烹饪演示视频。
4. **自定义上传**：用户可上传自己的菜谱文本（手动录入/文档导入）与实拍烹饪视频，与 AI 生成内容并存。

#### 1.3 项目目标
- **业务目标**：让用户"5 分钟内把一段菜谱文字变成一个带图带视频的完整菜谱页面"。
- **内容目标**：AI 生成与 UGC 上传双通道供给内容，避免冷启动期内容枯竭。
- **合规目标**：AI 生成内容按法规要求显著标识，用户上传内容有审核与版权承诺机制。

#### 1.4 范围界定
**范围内（In Scope）**
- Web 端（响应式）+ 微信小程序（第一期载体建议，后续再评估原生 App）
- 菜谱结构化管理、AI 文生图、AI 文生视频、用户上传（文本/图片/视频）
- 基础账号体系、内容审核、AI 内容标识

**范围外（Out of Scope，本期不做）**
- 电商（食材购买链接）、社区评论/关注体系（仅保留收藏/点赞最小集）
- 直接面向厨电（智能灶、蒸烤箱）的菜谱下发
- AI 视频剪辑（上传视频的自动剪辑、配音、字幕加工）——列为远期
- 多语言国际化

### 3. 调研方法与重点问题
- **用户访谈重点**：用户记录菜谱的现有方式（备忘录/纸质/截图）；对 AI 生成菜品图的接受度（"像不像"重要还是"好不好看"重要）；是否愿意为生成视频等待 1–5 分钟。
- **问卷重点**：上传自己烹饪视频的意愿与现有素材形态（横屏/竖屏、时长）；对 AI 内容标识的态度。
- **竞品拆解重点**：下厨房的结构化字段设计；懒饭的视频菜谱信息架构；即梦/可灵生成"食物"类内容的真实感与失败率。

## 第二部分：初步需求分析成果

### 4. 用户与场景分析

#### 4.1 用户角色
| 角色 | 描述 | 核心诉求 |
| --- | --- | --- |
| 家庭烹饪用户（主要） | 25–45 岁，家庭做饭，手机使用为主 | 找到靠谱菜谱、跟着步骤做、保存家传菜谱 |
| 内容创作者 | 美食博主、私域运营者 | 快速产出带图带视频的菜谱内容，降低拍摄成本 |
| 平台管理员 | 运营/审核人员 | 审核上传内容、管理生成配额、处置违规 |

#### 4.2 关键用户故事
1. 作为家庭用户，我能录入/粘贴一段菜谱文字，系统自动解析成结构化菜谱（菜名、食材、步骤），以便后续生成图片和视频。
2. 作为家庭用户，我能为菜谱一键生成封面图和每步配图，并可对不满意的图重新生成。
3. 作为家庭用户，我能把菜谱生成为一个 30–60 秒的烹饪演示短视频，配字幕与背景乐。
4. 作为家庭用户，我能上传自己实拍的烹饪视频并挂到我的菜谱下，与 AI 视频并列展示。
5. 作为创作者，我能批量导入菜谱文本（txt/markdown），批量生成配图。
6. 作为管理员，我能看到所有 AI 生成任务的记录与成本，能调整每用户每日生成配额。
7. 作为用户，我能看到 AI 生成内容带有明确标识，以区分实拍与生成。

#### 4.3 核心场景（端到端）
**场景 A（AI 全生成）**：粘贴"番茄炒蛋"菜谱文字 → 自动解析结构化 → 生成封面图 + 5 张步骤图（30 秒内）→ 发起视频生成（异步，2–5 分钟）→ 完成后菜谱页呈现"图 + 视频 + 分步文字"。
**场景 B（上传自有内容）**：手动新建菜谱 → 上传手机相册里的实拍视频（≤500MB）→ 系统转码为多码率 → 菜谱页展示，并标记"用户实拍"。
**场景 C（混合）**：AI 生成步骤图 + 用户替换其中两张为实拍图。

### 5. 功能需求

#### 5.1 功能架构总览
```
电子菜谱平台
├── 账号与用户中心（注册/登录/个人厨房/收藏/生成配额）
├── 菜谱管理（结构化编辑器 / 文本智能解析 / 导入导出）
├── AI 生成
│   ├── 文生图（封面图 / 步骤图 / 风格选择 / 重绘）
│   └── 文生视频（脚本化分镜 / 字幕 / 异步任务与通知）
├── 上传中心（菜谱文本导入 / 图片上传 / 视频上传与转码）
├── 浏览发现（首页 / 搜索 / 分类筛选 / 详情页）
└── 管理后台（内容审核 / 配额与成本 / 举报处置）
```

#### 5.2 功能清单与优先级（MoSCoW）
> P0=必须有（MVP），P1=应该有（第二迭代），P2=可以有（远期）

**5.2.1 菜谱管理**
| 编号 | 功能点 | 说明 | 优先级 |
| --- | --- | --- | --- |
| R-01 | 结构化菜谱编辑器 | 字段：菜名、简介、难度、时长、份量、食材（名称/用量）、步骤（文字/火候/时长）、小贴士 | P0 |
| R-02 | 菜谱文本智能解析 | 粘贴自由文本（或上传 txt/md），用 LLM 抽取为结构化字段，用户确认后保存 | P0 |
| R-03 | 菜谱 CRUD 与草稿 | 保存草稿、发布、编辑、删除（软删除） | P0 |
| R-04 | 菜谱导出 | 导出为图片长图/PDF（便于分享） | P1 |
| R-05 | 菜谱模板与复制 | 从已有菜谱复制修改 | P1 |

| I-06 | 批量生成 | 创作者批量任务队列 | P1 |

**5.2.3 AI 烹饪视频生成**

### 6. 非功能需求
| 类别 | 需求 |
| --- | --- |
| 性能 | 菜谱页首屏 ≤2s；文生图单张 ≤30s（API 同步等待）；文生视频为异步任务，成片 ≤5min（P95）；上传 500MB 视频分片并发，弱网可续传 |
| 可用性 | 服务可用性 ≥99.5%；生成任务失败自动重试 1 次，失败明确提示并返还配额 |
| 安全 | 视频/图片存储私有读（签名 URL 访问）；上传格式白名单与病毒扫描；接口鉴权与频控 |
| 合规 | AI 生成内容显著标识（《生成式人工智能服务管理暂行办法》《互联网信息服务深度合成管理规定》）；上传者需勾选版权承诺；食品安全免责声明（AI 视频仅为演示，实操请遵循食材安全常识） |
| 成本 | 单张图生成成本目标 ≤0.3 元；单条 60s 视频生成成本目标 ≤10 元（以实测为准，MVP 按每日每人 1 条视频、10 张图限流） |
| 可扩展 | 生成能力抽象为统一网关，支持切换/并行多家模型供应商 |

### 7. 技术可行性分析（待 S3 实测确认）

#### 7.1 文生图方案对比
| 方案 | 代表 | 优点 | 顾虑 |
| --- | --- | --- | --- |
| 国产 API | 智谱 CogView、通义万相、即梦 Seedream | 中文 prompt 理解好、食物摄影效果较好、无墙、按张计费清晰 | 单价略高 |
| 开源自部署 | SD/SDXL + ComfyUI | 成本可控、可微调菜品风格 | 需 GPU 运维、效果调优周期长 |
| 海外 API | DALL·E、Flux | 效果好 | 网络/结算/合规问题，不建议 |

**建议**：MVP 直接接国产 API（抽象 Provider 接口），量起来后评估自部署微调。

#### 7.2 文生视频方案对比
| 方案 | 代表 | 现状评估 |
| --- | --- | --- |
| 国产视频 API | 智谱 CogVideoX、可灵 Kling、即梦 | 单段 5–10s，食物特写可用，多镜头拼接由平台侧完成；单价较高（约 1–10 元/段，需实测） |
| 图生视频（降级） | 步骤图 → 图生视频 API | 成本低、与菜品一致性更好，作为 V-06 备选主推 |
| 自部署 | CogVideoX/Wan 开源 | GPU 成本高，MVP 不建议 |

**建议**：一期用"图生视频"为主（封面/步骤图动起来 + 字幕 + 转场），纯文生视频作为增强选项；两者都过异步任务队列。

#### 7.3 整体技术栈建议（待架构评审）
- 前端：Web（React/Vue3 响应式）+ 微信小程序（Taro/uni-app 跨端）
- 后端：主流 Web 框架（NestJS/Spring Boot）+ MySQL（业务）+ Redis（任务/配额）+ OSS（对象存储）+ 消息队列（生成/转码任务）
- 媒体处理：云厂商转码服务（HLS 多码率）或自建 FFmpeg worker
- AI 编排：统一"生成网关"封装 LLM 解析 / 文生图 / 文生视频 / TTS，带任务表、重试、成本记账

### 8. 数据模型草案（核心实体）
```
User(id, 昵称, 手机, 角色, 配额: 图/视频每日额度)
Recipe(id, user_id, 菜名, 简介, 难度, 时长, 份量, 分类[], 状态[草稿/发布/下架], 来源[AI解析/手动/导入])
Ingredient(id, recipe_id, 名称, 用量, 单位)
Step(id, recipe_id, 序号, 文字, 火候, 时长, 步骤图media_id?)
MediaAsset(id, recipe_id, 类型[封面图/步骤图/用户图/AI视频/用户视频], 来源[AI/上传], ai_flag, url, 状态)
GenerationTask(id, user_id, 类型[文生图/文生视频], prompt, 模型, 状态[排队/进行中/成功/失败], 成本, 耗时, 产物media_id)
```

### 9. 风险与应对
| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 文生视频质量不达预期（烹饪动作失真） | 高 | S3 提前实测；备选"图生视频+字幕动效"方案 V-06；产品文案定位为"演示视频"而非"实拍" |
| 生成成本失控 | 高 | 每日配额 + 灰度放量 + 成本看板 + 超额熔断 |
| AI 生成菜品图与实际成品差异引发投诉 | 中 | 醒目 AI 标识 + 详情页免责说明 |
| 上传视频版权纠纷 | 中 | 上传版权承诺书 + 投诉下架通道 + 水印 |
| 生成内容合规（不当内容） | 中 | 生成前后双向审核（prompt 拦截 + 产物机器审核） |
| 范围蔓延（社区/电商需求涌入） | 中 | 以本计划 1.4 节范围为准，变更走评审 |

### 11. MVP 验收标准（Definition of Done）
1. 粘贴 200 字以内菜谱文本，10 秒内完成结构化解析，字段准确率人工抽检 ≥90%。
2. 封面图生成成功率 ≥95%，单张 ≤30 秒，单菜谱可重绘并替换。
3. 视频生成任务端到端成功率 ≥90%，成片时长 30–60 秒，带步骤字幕。
4. 500MB 视频上传成功率 ≥99%（弱网断点续传可用），转码后小程序内流畅播放。
5. 所有 AI 生成图/视频均带显著标识；上传内容 100% 先审后显（或机审秒过+人工抽审）。
6. 单用户默认配额：每日 10 张图 + 1 条视频；配额耗尽有明确引导。
