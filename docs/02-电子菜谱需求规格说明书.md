## 1. 引言

### 1.1 目的
本文档将《需求分析计划》中的功能清单（R-/I-/V-/U-/B-/A- 系列）细化为可开发、可测试的需求规格：用例规约、页面信息架构、业务流程与状态机、数据库设计、API 草案、AI 能力设计规范与非功能指标。

### 1.2 术语
| 术语 | 定义 |
| --- | --- |
| 结构化菜谱 | 由菜名/食材/步骤等固定字段组成的菜谱数据，区别于自由文本 |
| 文生图 / 文生视频 | 由文字描述通过 AI 模型生成图片 / 视频的能力 |
| 图生视频（i2v） | 以已有图片为起点生成动态视频的降级方案（MVP 默认） |
| 生成任务 | 一次 AI 生成调用的异步封装，含状态、成本、产物 |
| 配额 | 每用户每日可用的图片/视频/解析次数 |
| AI 标识 | 依合规要求在 AI 生成内容上叠加的显著标识 |

### 1.3 系统边界（文字图）
```
用户端(Web/小程序) ─┐
                    ├─> 应用服务 ─┬─> MySQL / Redis / OSS
管理后台 ───────────┘             ├─> 生成网关 ─> LLM解析 / 文生图API / 文生视频API / TTS
                                  ├─> 转码服务(FFmpeg/云转码)
                                  └─> 内容审核服务(机审) + 人工审核后台
```

## 2. 用户角色与用例

### 2.1 角色
- **普通用户**：浏览、收藏、创建菜谱、使用生成与上传。
- **创作者**（普通用户的能力扩展，通过后台开通）：批量解析、批量生成。
- **管理员**：审核、配额配置、成本看板、处置举报。

### 2.3 用例规约（详细）

#### UC-01 菜谱文本智能解析
| 项 | 内容 |
| --- | --- |
| 前置条件 | 用户已登录；剩余解析配额（默认每日 20 次） |
| 主流程 | 1) 用户在编辑器点击"智能解析"；2) 粘贴/输入自由文本（≤3000 字）；3) 系统调用 LLM 抽取为结构化 JSON；4) 前端以表单形式回显（可编辑）；5) 用户确认后填入编辑器 |
| 分支流程 | 解析结果缺步骤或食材 → 对应字段标记"待补充"提示；解析置信度低 → 提示用户手动核对 |
| 异常流程 | LLM 超时(>20s)/报错 → 提示重试，不计配额；输出不符合 Schema → 自动重试 1 次后降级为"仅提取菜名" |
| 后置条件 | 解析记录写入 generation_task(type=PARSE)；配额 -1 |
| 验收标准 | 200 字典型菜谱文本，10s 内返回；字段准确率人工抽检 ≥90% |

#### UC-02 创建/编辑结构化菜谱
- 字段与校验见 §5.1；支持草稿自动保存（10 秒节流）；发布前校验必填项（菜名、≥1 食材、≥1 步骤）。
- 异常：并发编辑冲突 → 后保存者收到"内容已更新"提示并强制刷新。

#### UC-03 AI 生成菜谱图
| 项 | 内容 |
| --- | --- |
| 前置条件 | 菜谱已有菜名（图片配额默认每日 10 张） |
| 主流程 | 1) 在生成面板选择"封面图/步骤图/整批步骤图"；2) 选择风格（真实摄影/插画/简笔画）与画幅（1:1、3:4）；3) 系统组装 prompt（见 §8.2）；4) 同步等待（目标 ≤30s）出 1–4 张候选；5) 用户挑选或单张重绘；6) 选定图写为封面/步骤图 |
| 分支流程 | 重绘沿用同 prompt 变 seed；换风格则重组 prompt |
| 异常流程 | 生成失败 → 自动重试 1 次，仍失败则提示并返还本次配额 |
| 后置条件 | 产物写 media_asset(source=AI, ai_flag=1)，任务写 generation_task(type=IMAGE)，成本记账 |
| 验收标准 | 成功率 ≥95%；AI 图落库即打"AI 生成"水印标识 |

#### UC-04 AI 生成烹饪视频
| 项 | 内容 |
| --- | --- |
| 前置条件 | 菜谱为完整草稿或已发布（≥3 步骤）；视频配额默认每日 1 条 |
| 主流程 | 1) 用户点击"生成视频"；2) 系统先调用 LLM 生成分镜脚本并回显（可编辑文案，每镜 5–10s，总长 30–60s）；3) 用户确认后入队；4) 逐镜调用视频模型（默认图生视频：以封面/步骤图为起始帧）；5) 平台侧拼接片段、叠加步骤字幕、可选 BGM；6) 完成后站内/订阅消息通知，产物挂到菜谱 |
| 分支流程 | 单镜失败仅重生成该镜（镜级重试上限 2 次）；用户修改某镜文案 → 仅该镜重新入队 |
| 异常流程 | 整体失败 → 状态 FAILED + 失败原因展示，配额返还；服务中断 → 任务可由后台手动重派 |
| 后置条件 | 产物写 media_asset(kind=AI_VIDEO, ai_flag=1)；逐镜记录 provider/模型/耗时/成本 |
| 验收标准 | 端到端成功率 ≥90%，P95 ≤5 分钟；成片含步骤字幕与"AI 生成"标识 |

#### UC-05 上传实拍烹饪视频
| 项 | 内容 |
| --- | --- |
| 前置条件 | 已登录；视频为 mp4/mov，≤500MB、≤10 分钟 |
| 主流程 | 1) 上传中心申请分片上传凭证（直传 OSS）；2) 客户端分片（5MB/片）并发上传，断点续传；3) 完成后触发转码（HLS 多码率 360p/720p/1080p + 抽封面帧）；4) 机审通过 → 媒体状态 READY，可挂载到菜谱 |
| 分支流程 | 上传者须勾选版权承诺；每次上传记录留痕 |
| 异常流程 | 机审驳回 → 状态 BLOCKED 并告知原因；转码失败 → 保留原片提示重试 |
| 后置条件 | media_asset(source=UPLOAD, ai_flag=0) |
| 验收标准 | 500MB 上传成功率 ≥99%；弱网（模拟 3G 断流）可续传；转码后小程序内起播 ≤2s |

#### UC-06 上传菜谱文档导入
- 支持 txt / markdown（P0）与图片 OCR（P1，对应 U-01 中 OCR 部分）。单文件 ≤1MB、单次 ≤10 个菜谱；解析复用 UC-01 的 LLM 通道，逐条回显确认。

#### UC-07 浏览与搜索
- 关键词搜索命中字段及权重：菜名(5) > 食材名(3) > 步骤文字(1)；筛选维度：菜系、难度、时长区间、荤素、来源（实拍/AI 生成，对应 B-03 的 P1 项）；列表分页 20 条/页，封面懒加载。
- 详情页视频区：AI 视频与用户实拍视频以 Tab 并列；AI 内容角标"AI 生成"（A-04）。

#### UC-08 内容审核（管理员）
- 审核对象：上传图片/视频（先审后显：机审 PASS 直接放行，REVIEW 进人工队列，REJECT 拦截）；AI 生成产物抽审（默认抽检 5%，后台可配）。
- 人工队列操作：通过 / 驳回（需选原因）/ 永久封禁用户（需二次确认）。所有操作写 audit_record 与操作日志。

#### UC-09 配额与成本管理（管理员）
- 可配置项：每人每日图片数、视频数、解析数；创作者倍率；全局日成本上限（熔断：超限后所有生成任务排队并告警）。
- 成本看板指标：按日生成量、按类型成功率、P95 延迟、单均成本、供应商分布。

## 4. 关键业务流程与状态机

### 4.1 AI 视频生成任务状态机
```
DRAFT --确认脚本--> QUEUED --取队列--> GENERATING --全部镜完成--> STITCHING --成功--> SUCCESS
  ^                                                              |
  └------------------ 用户改稿(仅改镜) ---------------------+    +--> FAILED(镜级重试耗尽/供应商错误)
SUCCESS --用户选择--> 挂载到菜谱(PUBLISHED)
```
- 镜级重试上限 2 次；FAILED 返还配额；任务表记录每镜的 provider、模型、耗时、成本。

### 4.2 媒体资产状态机
```
上传类: UPLOADING → PROCESSING(转码/机审) → READY / BLOCKED / FAILED
生成类: GENERATING → READY(带AI水印) ；抽审命中 REVIEW → (人审) READY / BLOCKED
```

### 4.3 配额扣减规则
- 图/视频：**提交任务时预扣**，失败自动返还；重绘同一张不重复扣（10 分钟窗口内）；解析：成功才扣。
- 熔断：全局日成本超限 → 新任务排队（不扣配额），后台告警。

## 5. 功能详细需求与校验规则

### 5.1 菜谱字段与校验
| 字段 | 类型/限制 | 必填 | 说明 |
| --- | --- | --- | --- |
| 菜名 | 1–30 字符 | 是 | 唯一性不做强约束 |
| 简介 | ≤500 字 | 否 | — |
| 难度 | 1–5 | 是 | 默认 2 |
| 烹饪时长 | 1–1440 分钟 | 是 | — |
| 份量 | 1–99 人份 | 是 | — |
| 菜系 | 枚举：川/粤/湘/鲁/江浙/西餐/日料/烘焙/其他 | 否 | — |
| 食材 | 1–50 项；名称 ≤20 字、用量 ≤20 字（支持"适量"） | ≥1 | — |
| 步骤 | 1–30 步；每步 ≤500 字；火候枚举(小火/中火/大火/无需)；每步时长可选 | ≥1 | 支持拖拽排序 |
| 小贴士 | ≤300 字 | 否 | — |

### 5.2 上传限制汇总
| 类型 | 格式 | 大小/时长 | 数量 |
| --- | --- | --- | --- |
| 图片 | jpg/png/webp | 单张 ≤10MB | 每菜谱 ≤20 张 |
| 视频 | mp4/mov | ≤500MB、≤10min | 每菜谱 ≤3 条 |
| 文档 | txt/md（P1：jpg/png OCR） | ≤1MB | 单次 ≤10 个菜谱 |

### 5.3 内容安全规则（对应 A-03 / A-04）
- 所有 UGC 上传：先审后显；生成 prompt 与生成产物双向机审（色情、涉政、暴恐、广告二维码）。
- AI 生成图/视频：右下角固定"AI 生成"水印（服务端渲染，不可通过前端手段去除）+ 详情页字段级标识；导出物同样带标识。
- 详情页固定食品安全免责声明："AI 生成内容仅供参考演示，实际烹饪请遵循食品安全常识。"

## 6. 数据库设计（MySQL 8.0 / utf8mb4，核心 DDL）

```sql
CREATE TABLE `user` (
  `id`         BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `nickname`   VARCHAR(32)  NOT NULL,
  `phone`      VARCHAR(20)  NOT NULL,
  `role`       ENUM('USER','CREATOR','ADMIN') NOT NULL DEFAULT 'USER',
  `status`     TINYINT NOT NULL DEFAULT 0 COMMENT '0正常 1封禁',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY `uk_phone` (`phone`)
) ENGINE=InnoDB;

CREATE TABLE `recipe` (
  `id`             BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `user_id`        BIGINT UNSIGNED NOT NULL,
  `title`          VARCHAR(60)  NOT NULL,
  `intro`          VARCHAR(500) DEFAULT NULL,
  `difficulty`     TINYINT NOT NULL DEFAULT 2 COMMENT '1-5',
  `cook_minutes`   INT NOT NULL,
  `servings`       TINYINT NOT NULL DEFAULT 2,
  `cuisine`        VARCHAR(20) DEFAULT NULL,
  `source`         ENUM('MANUAL','PARSE','IMPORT') NOT NULL DEFAULT 'MANUAL',
  `status`         ENUM('DRAFT','PUBLISHED','REMOVED') NOT NULL DEFAULT 'DRAFT',
  `cover_media_id` BIGINT UNSIGNED DEFAULT NULL,
  `created_at`     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY `idx_user_status` (`user_id`,`status`),
  KEY `idx_status_created` (`status`,`created_at`),
  FULLTEXT KEY `ft_title` (`title`)
) ENGINE=InnoDB;

CREATE TABLE `ingredient` (
  `id`        BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `recipe_id` BIGINT UNSIGNED NOT NULL,
  `name`      VARCHAR(20) NOT NULL,
  `quantity`  VARCHAR(20) NOT NULL,
  KEY `idx_recipe` (`recipe_id`),
  KEY `idx_name` (`name`)
) ENGINE=InnoDB;

CREATE TABLE `recipe_step` (
  `id`             BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `recipe_id`      BIGINT UNSIGNED NOT NULL,
  `seq`            TINYINT NOT NULL,
  `text`           VARCHAR(1000) NOT NULL,
  `heat`           ENUM('LOW','MID','HIGH','NONE') NOT NULL DEFAULT 'NONE',
  `duration_sec`   INT DEFAULT NULL,
  `image_media_id` BIGINT UNSIGNED DEFAULT NULL,
  UNIQUE KEY `uk_recipe_seq` (`recipe_id`,`seq`)
) ENGINE=InnoDB;

CREATE TABLE `media_asset` (
  `id`          BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `recipe_id`   BIGINT UNSIGNED DEFAULT NULL,
  `user_id`     BIGINT UNSIGNED NOT NULL,
  `kind`        ENUM('COVER','STEP','USER_IMAGE','AI_IMAGE','AI_VIDEO','USER_VIDEO') NOT NULL,
  `source`      ENUM('AI','UPLOAD') NOT NULL,
  `ai_flag`     TINYINT NOT NULL DEFAULT 0,
  `oss_key`     VARCHAR(255) NOT NULL,
  `mime`        VARCHAR(50) NOT NULL,
  `size_bytes`  BIGINT NOT NULL DEFAULT 0,
  `width`       INT DEFAULT NULL,
  `height`      INT DEFAULT NULL,
  `duration_ms` INT DEFAULT NULL,
  `status`      ENUM('UPLOADING','PROCESSING','READY','REVIEW','BLOCKED','FAILED') NOT NULL DEFAULT 'UPLOADING',
  `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY `idx_recipe_kind` (`recipe_id`,`kind`),
  KEY `idx_status` (`status`)
) ENGINE=InnoDB;

CREATE TABLE `generation_task` (
  `id`             BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `user_id`        BIGINT UNSIGNED NOT NULL,
  `recipe_id`      BIGINT UNSIGNED DEFAULT NULL,
  `type`           ENUM('PARSE','IMAGE','VIDEO_SCRIPT','VIDEO') NOT NULL,
  `status`         ENUM('DRAFT','QUEUED','RUNNING','STITCHING','SUCCESS','FAILED') NOT NULL,
  `provider`       VARCHAR(32) DEFAULT NULL,
  `model`          VARCHAR(64) DEFAULT NULL,
  `prompt`         TEXT,
  `params`         JSON DEFAULT NULL COMMENT '风格/画幅/分镜脚本等',
  `result_media_ids` JSON DEFAULT NULL,
  `cost_cents`     INT NOT NULL DEFAULT 0,
  `latency_ms`     INT DEFAULT NULL,
  `error`          VARCHAR(500) DEFAULT NULL,
  `created_at`     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `finished_at`    DATETIME DEFAULT NULL,
  KEY `idx_user_created` (`user_id`,`created_at`),
  KEY `idx_status_type` (`status`,`type`)
) ENGINE=InnoDB;

CREATE TABLE `quota_usage` (
  `id`           BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `user_id`      BIGINT UNSIGNED NOT NULL,
  `day`          DATE NOT NULL,
  `parse_count`  INT NOT NULL DEFAULT 0,
  `image_count`  INT NOT NULL DEFAULT 0,
  `video_count`  INT NOT NULL DEFAULT 0,
  UNIQUE KEY `uk_user_day` (`user_id`,`day`)
) ENGINE=InnoDB;

CREATE TABLE `audit_record` (
  `id`          BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  `media_id`    BIGINT UNSIGNED DEFAULT NULL,
  `recipe_id`   BIGINT UNSIGNED DEFAULT NULL,
  `kind`        ENUM('MACHINE','HUMAN') NOT NULL,
  `verdict`     ENUM('PASS','REJECT','REVIEW') NOT NULL,
  `reason`      VARCHAR(200) DEFAULT NULL,
  `operator_id` BIGINT UNSIGNED DEFAULT NULL,
  `created_at`  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY `idx_media` (`media_id`)
) ENGINE=InnoDB;

CREATE TABLE `admin_config` (
  `cfg_key`   VARCHAR(50) PRIMARY KEY,
  `cfg_value` JSON NOT NULL,
```

## 8. AI 能力设计规范

### 8.1 供应商抽象（生成网关）
```typescript
interface ImageProvider {
  generate(req: { prompt: string; ratio: '1:1'|'3:4'; count: number }): Promise<{ url: string; seed?: string }[]>;
}
interface VideoProvider {
  // mode: 't2v' 文生视频 | 'i2v' 图生视频（MVP 默认 i2v）
  submit(req: { mode: 't2v'|'i2v'; prompt: string; imageUrl?: string; durationSec: number }): Promise<{ handle: string }>;
  poll(handle: string): Promise<{ status: 'RUNNING'|'DONE'|'FAILED'; videoUrl?: string }>;
}
```
- 候选实现：文生图（智谱 CogView / 通义万相）、视频（CogVideoX / 可灵，i2v 优先）、LLM 解析与分镜（GLM / 通义）、TTS 与 BGM 预置曲库。实测对比见《电子菜谱-技术可行性验证方案》。
- 网关职责：供应商路由与降级、重试、成本记账、熔断、prompt 机审前置。

### 8.2 Prompt 模板（草案）
- 封面图：`美食摄影，{菜名}成品，主料：{食材前3}，{风格词}，45度俯拍，自然柔和光线，浅景深，白瓷盘木质桌面，色泽诱人，细节清晰`（风格词：真实摄影/手绘插画/极简线稿）
- 步骤图：`烹饪过程图，{菜名}第{n}步：{步骤文字(≤60字)}，{风格词}，画面聚焦锅内动作，无文字水印`
- 分镜脚本（LLM 输出 Schema）：
```json
{ "title": "…", "totalDurationSec": 45,
  "shots": [ { "seq": 1, "durationSec": 6, "shotType": "特写|中景",
               "action": "画面内容描述", "narration": "旁白文案",
               "onScreenText": "步骤字幕" } ] }
```

### 8.3 合规实现要点
- AI 产物落库时即叠加不可去除的角标水印（服务端渲染）；元数据同时写入 ai_flag。
- 详情页、分享卡片、导出长图三处均展示"AI 生成"标识。

## 9. 非功能指标与可观测性
| 指标 | 目标 | 告警阈值 |
| --- | --- | --- |
| 图片生成成功率 | ≥95% | <90% 告警 |
| 视频端到端成功率 | ≥90% | <80% 告警 |
| 图片 P95 延迟 | ≤30s | >60s |
| 视频 P95 完成时长 | ≤5min | >10min |
| 上传 500MB 成功率 | ≥99% | — |
| 单图成本 | ≤0.3 元 | 单日均值 >0.4 元告警 |
| 单视频成本 | ≤10 元 | 单日均值 >12 元告警 |
| 全局日成本熔断 | 超预算即排队 | 触发即电话告警 |

埋点：解析/生成/上传三漏斗（进入→提交→成功）、失败原因分布、任务中心停留时长。
