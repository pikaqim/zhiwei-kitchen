## 1. 验证目标与结论口径

本阶段必须回答四个问题：

| # | 问题 | 产出 | 决策影响 |
| --- | --- | --- | --- |
| Q1 | 文生图对"中餐成品/烹饪动作"的真实感与可用率？ | 《生图评测报告》 | 确定 I-01~I-04 的供应商与风格基线 |
| Q2 | 文生视频（t2v）与图生视频（i2v）对烹饪演示的质量与单段成本？ | 《视频评测报告》 | 决定 V 系列走 t2v 还是降级 i2v（V-06 备选） |
| Q3 | LLM 菜谱解析/分镜脚本的结构化准确率？ | 《解析评测报告》 | 验收指标"抽检准确率 ≥90%"是否可达成（UC-01） |
| Q4 | 各家 API 的限流、并发、结算方式？ | 《接入评估表》 | 生成网关的供应商路由与熔断参数 |

**结论只允许三种**：
- ✅ **通过**：达到 §5 决策阈值，按主方案（t2v 增强 + i2v 为主）进入开发；
- ⚠️ **降级**：t2v 不达标但 i2v 达标 → 一期只做 i2v + 字幕动效（对应计划文档 V-06），t2v 转 M2 后评估；
- ❌ **阻断**：两者均不达标 → 视频 P0 范围重议，需求评审前必须上报。

## 3. 统一评测测试集（20 道代表性菜谱）

测试集 purpose：覆盖 prompt 难度光谱，所有生图/生视频/解析评测共用同一输入，保证横向可比。菜谱文本统一控制在 150–300 字（贴近 UC-01 的真实输入形态）。

| 组别 | 菜例（各 5 道） | 难度点 |
| --- | --- | --- |
| A 家常热炒 | 番茄炒蛋、鱼香肉丝、宫保鸡丁、麻婆豆腐、青椒肉丝 | 锅气动作、颜色层次、汤汁质感 |
| B 汤羹炖煮 | 番茄蛋汤、玉米排骨汤、红烧肉、清蒸鲈鱼、冬瓜丸子汤 | 液体质感、蒸汽、成品完整性（整鱼/整块） |
| C 烘焙面点 | 戚风蛋糕、曲奇、葱花饼、手工馒头、蛋挞 | 外形几何规整度、发酵面点 realism |
| D 西餐轻食 | 意面、牛排、凯撒沙拉、三明治、煎蛋卷 | 西式摆盘、熟度表现（牛排 rare/medium） |

每道菜例附带：结构化菜谱 JSON（人工标注的金标准，用于算解析准确率）、3 个关键步骤文字（用于步骤图/分镜评测）。

## 4. 评测方法

### 4.1 生图评测（Q1）
- 每家供应商 × 4 组 × 5 道 × 2 风格（真实摄影/插画）= 每家 40 张；画幅 3:4。
- **自动指标**：接口成功率、P50/P95 延迟、单张成本、prompt 违反率（出现文字水印/多余手指等，人工标）。
- **人工评分**（3 人独立盲评，1–5 分）：
  - 食物辨识度：能不能一眼认出是这道菜；
  - 摄影质感：光线、构图、食欲感；
  - 步骤还原度：是否表现了步骤文字所述动作。
- 每图记录：provider、model、prompt、seed、耗时、费用、三项评分。

### 4.2 视频评测（Q2，本阶段核心）
- 每家 t2v 与 i2v 各跑：4 组 × 5 道中抽 10 道 × 2 段（关键步骤各 1 段，5–10s）= 每家 20 段。
- **人工评分**（1–5 分）：
  - 动作真实性：翻炒/倒油/翻面等是否符合物理常识（食物类最大失真源）；
  - 食物一致性：始末帧食物是否为同一道菜（i2v 重点）；
  - 可用度：能否直接作为演示视频片段（卡顿/闪烁/畸形判定）。
- 同时实测：单段成本、排队时长、生成时长 P95、并发上限（逐步加压至 429）。
- **拼接链路验证**：取最优供应商的 6–8 段片段，走一遍 FFmpeg 拼接 + 字幕烧录 + BGM 混音，产出 1 条 45s 完整样片（对应 UC-04 的 STITCHING 环节），供需求评审现场演示。

### 4.3 LLM 解析评测（Q3）
- 20 道金标准菜谱文本 → 逐道调用解析 → 与金标准 JSON 比对。
- 指标：菜名/食材名/用量/步骤数/步骤文本的字段级准确率；Schema 遵守率（不重试直接合法输出比例）；单次成本与延迟。
- 抽 20 条乱序文本（无换行、口语化、含错别字）测鲁棒性。

### 4.4 限流与结算（Q4）
- 对每家记录：免费额度、RPM/并发限制、超额行为（排队 or 报错）、结算方式、发票/主体合规性、SLA。
- 输出《接入评估表》，作为生成网关熔断参数（SRS §4.3）的输入。

## 5. 决策阈值与评分表模板

| 指标 | 通过阈值 | 降级触发 |
| --- | --- | --- |
| 生图食物辨识度均分 | ≥4.0/5 | <3.5 → 收窄为"仅封面图可用，步骤图禁用" |
| 生图成功率 | ≥95% | <90% → 换备选供应商 |
| t2v 动作真实性均分 | ≥3.8/5 | <3.8 → 一期转 i2v（V-06） |
| i2v 动作真实性均分 | ≥3.8/5 | <3.8 → 视频能力整体阻断，上报重议 |
| i2v 食物一致性均分 | ≥4.0/5 | <3.5 → 每镜换用"步骤图为首帧"策略再测一轮 |
| 视频单段成本（i2v） | ≤1.5 元 | >2.5 元 → 重议配额（每日 1 条可能下调）或换供应商 |
| 45s 样片端到端成本 | ≤10 元 | >12 元 → 同上 |
| 解析字段准确率 | ≥90% | <85% → 在编辑器默认展开"待核对"高亮（UC-01 分支） |

**评分表模板**（每个 provider × 样本一行，落 CSV/表格便于汇总）：

```
provider, model, capability(t2v/i2v/t2i/parse), sample_id, prompt, seed,
latency_ms, cost_cents, success(0/1),
score_realism(1-5), score_consistency(1-5), score_usability(1-5), notes
```

## 6. 执行安排

| 事项 | 说明 |
| --- | --- |
| 人力 | 后端 1 人（Provider 抽象 + 评测脚本）+ 产品 1 人（人工盲评组织）+ 视觉/算法 1 人（评分仲裁） |
| 工期 | 5 个工作日：D1 抽象层+脚本，D2–D3 批量跑测，D3 并行拼接样片，D4 盲评+汇总，D5 报告与决策会 |
| 预算 | 评测消耗预估 ≤2000 元（生图 160 张 + 视频 80 段 + LLM 调用），实报实销、逐日记录 |
| 产物 | 《生图/视频/解析评测报告》三份 + 《接入评估表》 + 1 条 45s 演示样片 + 选型决策纪要 |

## 7. 风险与预案
| 风险 | 预案 |
| --- | --- |
| 某供应商 API 中途改版/停售 | 抽象层隔离，评测脚本按 provider 插件化，可当日换测 |
| 人工评分主观漂移 | 3 人盲评 + 分歧项仲裁；先评 5 张校准样对齐标准 |
| 视频评测预算超支 | 先用每家 5 段做初筛，入围者再加测到 20 段 |
| 评测结论与商业条款冲突（如独占折扣） | 决策会引入成本模型复算，不只看单价 |
